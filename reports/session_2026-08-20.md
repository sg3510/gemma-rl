## Found

1. **Tool-call looping is the dominant telecom failure** — 45% of NextBit
   rollouts repeat one identical call until the step cap.
   [tool_call_looping.md](tool_call_looping.md), D29
2. **It is a self-reinforcing attractor, not a plumbing bug.** Prefix replay:
   repeat probability 23% → 87% → 97% at 2, 5, 8 identical results. Wire format
   is clean; payload normalisation, prompt guidance and canonical `top_p` all
   change nothing.
3. **Removing the looped tool does not help — the loop migrates** to the next
   available read (86% loop rate without `get_details_by_id`).
4. **The backend dominates the entry rate.** Identical tasks and weights:
   NextBit 32% loop / 60% pass, DeepInfra fp8 10% / 82%, **Novita 6% / 91%**
   (p=0.003). Precision is not the axis. [provider_loop_rates.md](provider_loop_rates.md), D30
5. **The real cause is the agent/customer tool boundary.** 66% of Novita
   rollouts call a *customer device tool* they do not have. NextBit's constrained
   decoding makes that impossible to emit, so the model substitutes the nearest
   legal read and loops forever. **A serving-side guardrail turned a recoverable
   mistake into an absorbing loop.** D31
6. **Sampling parameters were never pinned** — `top_p`/`top_k` fell back to each
   host's undocumented defaults. Gemma ships `top_k=64, top_p=0.95`; NextBit
   cannot serve `top_k` at all.
7. **The balanced `test` split is not the task pool.** Pool-drawn mms tasks:
   pass@1 23.8%, pass@4 65.0%, 65% frontier, **zero tasks solved 4/4** — a much
   better RL target than the split's 64% with 12 of 40 saturated.
8. **One sentence of prompt eliminates looping entirely.** Both a verbose and a
   one-line statement of the tool boundary take loop rate 7% → **0%** and the
   longest silent chain 59 → 2. Hallucination falls 66% → 7% (verbose) or 28%
   (one-line); traces shrink 15–20%. **Success does not improve** — paired
   deltas −5.6% (p=0.22) and −8.5% (p=0.08). Fixing the error rate did not fix
   outcomes, and the softer wording made transfers-to-human *worse* (67% vs
   55%), contrary to the passivity theory it was written to test.

## Corrected

- Frontier share 67% → **56%**: the original binned tasks by success count while
  ignoring unequal trial counts.
- Loop metrics counted **customer** tool calls (≈half of all calls). Agent-only
  now.
- Loop breaker: force-scoring 0 was wrong (loops often occur *after* the task is
  solved). Terminate-and-evaluate instead. Threshold recalibrated 5 → 7 → 9 as
  the corpus grew; **not adopted for evaluation** — costs ~1% of successes for
  ~9% of tokens, and is irrelevant under prompt clarification.
- Headline pass@1 is reported **macro** (mean of per-task rates), not micro.

## Serving / throughput

- Pinned stack moves **NextBit → Novita**, sampling sent explicitly.
- Customer simulator served **direct** (all six OpenRouter endpoints for it are
  Google; direct is the same serving minus a proxy hop, 0.9s vs 1.82s).
- **Multi-route pools** (`tau2probe/routes.py`): agent = OpenRouter→Novita +
  Vercel→novita (pinning verified enforced); customer = Gemini direct +
  OpenRouter + Vercel. Independent limiters, round-robin + failover.
- Vercel AI Gateway serves gemma via `gmicloud, novita, parasail, **vertex**` —
  first-party Vertex Gemma with no endpoint to deploy, relevant to Stage A.
